> 目标：这 20 条能脱口而出，其他都可以查。

## 一、20 条必背

### 第 1 课

1. `delta` 是“过了多久”，不是“画了几帧”。写死 `1/60` 在 120Hz 上快一倍、掉帧时慢一半。
2. 改了 `camera.aspect` / `fov` 必须 `updateProjectionMatrix()`——渲染用的是**矩阵**，不是属性。
3. `setPixelRatio(min(dpr, 2))`：像素数是 dpr 的平方，3 倍屏是 2 倍屏的 2.25 倍开销。

### 第 2 课

4. 世界矩阵 = 父级世界矩阵 × 本地矩阵；本地矩阵 = `T · R · S`（先缩放、再旋转、后平移）。
5. `Euler` 的 `order='XYZ'` 表示 `Rx·Ry·Rz`，**从右往左作用**；赋值顺序 ≠ 作用顺序。
6. 固定不变的姿态放**外层**，持续变化的量放**内层**——倾角在外、自转在内。
7. 绝对时间驱动时，所有常量都必须写进同一个公式，否则每帧被覆盖（`phase` 的坑）。

### 第 3 课

8. 几何体 = 顶点属性 + 索引。`顶点数 = position 长度 / 3`。
9. `三角形数 = 索引长度 / 3`；索引长度 = 三角形数 × 3。
10. 逆时针 = 正面；写反了就是“从外面看不见”。
11. 顶点是**属性组**（位置 + 法线 + UV），位置相同但法线不同 → 必须拆开（立方体 24 顶点）。
12. 改完 `array` 必须 `needsUpdate = true`；形状变了还要 `computeVertexNormals()`。

### 第 4 课

13. 金属没有漫反射：`metalness = 1 → kD = 0`，颜色全部来自反射。
14. `roughness` 改的是高光**形状**；能量守恒下，变宽必然变暗。
15. `scene.environment` 需要 **PMREM** 纹理；Lambert/Phong 的 shader 只采 `ENVMAP_TYPE_CUBE`，所以看起来“不吃环境光”。

### 第 5 课

16. 一张图的 128 是“人眼中的中灰”还是“0.5 这个数”？前者设 sRGB，后者（法线/粗糙度/AO）不能设。
17. 漏设 sRGB = **暗部被抬亮** = 画面发灰发白，不是变暗。
18. `wrap` 管“超出 0~1 怎么办”，`repeat` 管“铺几遍”——只设 `repeat` 会得到边缘拉伸。
19. mipmap 治“缩太小”，各向异性治“斜着看”；正对着看两者都不参与。

### 第 6 课

20. `scene.remove()` 不释放显存；要 `geometry / material / texture` 各自 `dispose()`。

## 二、三张计算卡

```
显存 = 宽 × 高 × 4 字节，含 mipmap × 1.33
     1024² = 4 MB    2048² = 16 MB    4096² = 64 MB

索引长度 = 三角形数 × 3
三角形数 = 网格格数 × 2

索引位数：顶点数 > 65535 → Uint32，否则 Uint16
```

## 三、判断“这个技术解决哪个问题”

失分最多的一类：说不清某个技术**为什么存在**。四选一：

| 技术 | 解决 | 一句话 |
|---|---|---|
| `delta` | 时间 | 让运动与帧率解耦 |
| `needsUpdate` | CPU→GPU | 数据改了要重传 |
| mipmap | GPU 采样 | 缩太小时防混叠 |
| `anisotropy` | GPU 采样 | 斜视时沿长轴多采 |
| `dispose` | 显存 | GPU 资源不会自己回收 |
| `colorSpace` | 颜色编码 | 颜色要解码，数据不能 |
| **Draco** | **传输** | 压几何，省下载体积（不省显存） |
| **KTX2** | **显存** | 压纹理，GPU 直接采样（也省传输） |
| `PMREM` | 环境光 | 预过滤环境图，只有 PBR 能采 |
| `InstancedMesh` | draw call | 形状相同、位置不同 |
| `LoadingManager` | 加载 | 汇总**文件个数**，不是字节 |

> 口诀：**先问“它省的是时间、下载、显存，还是 CPU/GPU 的活？”**
